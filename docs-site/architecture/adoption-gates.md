# Passport adoption gates

**Snapshot: 15 November 2026.** This is the 0.2.0 decision map for [issue #244](https://github.com/input-output-hk/midnight-passport-sdk/issues/244). It maps the [Passport v1.0 promises](https://github.com/midnightntwrk/passport/blob/99062671d939641cb9ed9274d3d18fce764d539a/docs/plans/PROMISES.md) and [C1–C26 inventory](https://github.com/midnightntwrk/passport/blob/99062671d939641cb9ed9274d3d18fce764d539a/docs/plans/components/README.md) at architecture revision `9906267` to this SDK's merged source at [`3546769`](https://github.com/input-output-hk/midnight-passport-sdk/tree/3546769c2f3ad94485768d8539869d16789bdba6). The published package remains [RC9](https://github.com/input-output-hk/midnight-passport-sdk/releases/tag/sdk-v0.1.0-rc9). “Subset” below means a bounded source path, not full promise conformance or release qualification. [Architecture conformance](/architecture/conformance) gives the evidence behind each supported subset.

The SDK owns reusable account flows, ports, adapters, and exact binding capabilities. A wallet or application host owns user consent, credential access, storage, service selection, and recovery UI. The Passport product and external standard owners must supply the namespace, DID, credential, cross-chain, and interoperable service policies that cannot be established by this package alone. Proposed and Draft standards remain at those statuses in the [dated standards map](/architecture/standards); source compatibility is a separate test.

## C1–C26 component ownership

The “standard/owner” column names the design authority or current maturity. A [Proposed MIP](/architecture/standards) is an adoption input, not a ratified compatibility guarantee. Gates are additional to full local and hosted checks on the exact source head.

| Component | SDK responsibility now | Host/product responsibility; standard or external owner | Adoption gate |

| C1 Account custody | Pinned `acc-s3r1.1` binding and typed subset. | Host deploys and retains account state; MIP-0012/0013 Proposed. | New binding needs source, ABI, artifact, maintenance and native migration decision; [#82](https://github.com/input-output-hk/midnight-passport-sdk/issues/82). |
| C2 Name service | Optional checked port; local transitional registry reader. | Host selects provider; Midnames/MIP-0007 Proposed; Passport owns namespace. | Authoritative operation-context contract target, independent chain read, owner continuity; [#315](https://github.com/input-output-hk/midnight-passport-sdk/issues/315), [#247](https://github.com/input-output-hk/midnight-passport-sdk/issues/247). |
| C3 DID surface | Absent. | Passport identity workstream; DID method undecided. | Approved method and interoperable resolution with no implied ACC custody from an identifier. |
| C4 Asset custody | Selected deposits and exact-value withdrawals. | Host wallet funds/fees; MIP-0012 Proposed. | Complete supported asset/circuit matrix and private-change accounting; [#82](https://github.com/input-output-hk/midnight-passport-sdk/issues/82), [#201](https://github.com/input-output-hk/midnight-passport-sdk/issues/201). |

## Cryptographic and release decisions

| Candidate | Current decision | Evidence required before adoption |
| --- | --- | --- |
| Alternative authoriser arms | Keep the pinned P-256 and PRF-derived JubJub subsets. A new signer, curve, envelope or authoriser set changes the compatibility axis. | Exact source/codec/circuit ABI and key recipe pins; proof-backed positive and revoked/stale negatives; real credential/provider checks. [#82](https://github.com/input-output-hk/midnight-passport-sdk/issues/82). |
| Viewing envelope and recovery | Do not combine a legacy wrapping scheme with the proposed offline guardian-reader envelope or claim either restores a passkey-derived ordinary wallet. | Pick one versioned profile; prove refresh across key rotations, retained viewing generations, same-name/ACC recovery, secrecy and independent helpers. [#240](https://github.com/input-output-hk/midnight-passport-sdk/issues/240). |
| Domain separation | Keep the current pinned derivations. MIP-0021 is Proposed. | Per-use domain inventory, collision/cross-protocol negatives and migration plan tied to the exact binding; [#244](https://github.com/input-output-hk/midnight-passport-sdk/issues/244). |
| Alternate compiler/prover and contract artifacts | Experiments do not qualify an ACC deployment or an SDK release. | A changed contract, ABI or verifier needs exact artifact hashes, a binding/version decision, and native plus installed-consumer acceptance. A runtime-only prover replacement against unchanged artifacts needs exact-artifact interoperability and privacy qualification, without automatically changing the binding ID. [#82](https://github.com/input-output-hk/midnight-passport-sdk/issues/82), [#241](https://github.com/input-output-hk/midnight-passport-sdk/issues/241). |

The bounded 0.2.0 candidate is the [seven-issue Midnames journey](/architecture/milestone-0.2.0#next-seven-issue-delivery-goal). [#20](https://github.com/input-output-hk/midnight-passport-sdk/issues/20), [#23](https://github.com/input-output-hk/midnight-passport-sdk/issues/23), [#82](https://github.com/input-output-hk/midnight-passport-sdk/issues/82), [#201](https://github.com/input-output-hk/midnight-passport-sdk/issues/201), [#240](https://github.com/input-output-hk/midnight-passport-sdk/issues/240), [#241](https://github.com/input-output-hk/midnight-passport-sdk/issues/241), and [#242](https://github.com/input-output-hk/midnight-passport-sdk/issues/242) retain separate acceptance. C25 and P9/P10 are upstream-dependent; this map creates no duplicate implementation ticket and no commitment to deliver the entire Passport v1.0 architecture in the next package release.
