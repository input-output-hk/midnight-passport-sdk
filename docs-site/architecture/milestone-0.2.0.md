# What remains for 0.2.0?

**Snapshot: 13 November 2026.** The [0.2.0 milestone](https://github.com/input-output-hk/midnight-passport-sdk/milestone/2) has 15 open issues and no closed issues. An open issue may already have a tested subset; its remaining acceptance is still open. The source compared here is [`passport-acc-prototype` at `8117a10`](https://github.com/input-output-hk/midnight-passport-sdk/tree/8117a10f9938093d21d656f8c504398957c58ac9). The published package release remains [`0.1.0-rc9`](https://github.com/input-output-hk/midnight-passport-sdk/releases/tag/sdk-v0.1.0-rc9). Source and localnet results do not silently become release, provider, or public-network qualifications.

The milestone groups candidate work; assigning an issue to it does not mean every Passport v1.0 promise must ship in one SDK release. [Architecture conformance](/architecture/conformance) separates source capability, test evidence, and the broader Passport target.

## Next bounded implementation slice

Finish the original demo's **post-ACC name claim step** under [#316](https://github.com/input-output-hk/midnight-passport-sdk/issues/316). Reuse the existing opt-in preparation and sponsor fence after the ACC address is known. Retain one credential-and-network-scoped claim intent through reload, show *pending Passport setup* until the original claim and current registry record agree, and make retry recover that original rather than deploy another ACC. Test the create/open handoff and interruptions with the synthetic browser before attempting a new native run. This gives the local demo a visible end-to-end path while keeping the separate name-owner total-loss and public-namespace gates explicit.

After that, a user-run independent sender for [#317](https://github.com/input-output-hk/midnight-passport-sdk/issues/317) can consume the same real resolver. [#318](https://github.com/input-output-hk/midnight-passport-sdk/issues/318) depends on the named recipient and a durable two-leg owner journey. Online activation of any Midnames profile waits for [#315](https://github.com/input-output-hk/midnight-passport-sdk/issues/315)'s known-name read-only smoke. Native qualification uses a separately authorised, owned stack; neither a documentation build nor a synthetic browser test substitutes for it.
